# Export Folder Structure — Cloud Shell

This document describes the two main working directories used during
the BigQuery → Terraform export and propagation workflow in Cloud Shell.

---

## `~/gcp-exports/`

**Created by:** `export_bq_to_tf.py` (supplementing `gcloud beta resource-config bulk-export`)

**Purpose:** Raw Terraform HCL files exported directly from BigQuery API,
one file per resource. This is the **source of truth** from the live GCP environments.
Files are never edited here — treat this folder as read-only after export.

**Folder structure:**

```
gcp-exports/
└── prod/
    └── projects/
        └── tefde-gcp-fastoss-prod/
            ├── BigQueryDataset/
            │   └── {dataset_id}.tf
            ├── BigQueryTable/
            │   └── {dataset_id}_{table_id}.tf
            └── BigQueryRoutine/
                └── {dataset_id}_{routine_id}.tf
```

The same structure repeats for each exported environment (`prod`, `prod-gke`, `test`, etc.)
as separate top-level subfolders.

**What each `.tf` file contains:**

| Resource type | File contains |
|---|---|
| `BigQueryDataset` | `resource "google_bigquery_dataset"` block with location, labels, description |
| `BigQueryTable` | `resource "google_bigquery_table"` block with schema, view/MV query, partitioning, clustering, encryption, labels |
| `BigQueryRoutine` | `resource "google_bigquery_routine"` block with routine type, language, body, arguments |

Every file also contains a commented `# terraform import ...` line at the top
that `organize_tf_export_flat.py` uses to generate `imports.tf`.

**How to regenerate:**

```bash
# Export prod (supplements existing files, skips those already present)
python ~/remediation/"TEF remediation/scripts/export_bq_to_tf.py" \
  --project tefde-gcp-fastoss-prod \
  --exports-dir ~/gcp-exports \
  --env prod

# Force full regeneration (overwrites existing files)
python ~/remediation/"TEF remediation/scripts/export_bq_to_tf.py" \
  --project tefde-gcp-fastoss-prod \
  --exports-dir ~/gcp-exports \
  --env prod \
  --overwrite
```

## `~/terraform-export-flat/`

**Created by:** `organize_tf_export_flat.py` (reorganises `gcp-exports/`) and
`propagate_tf_env.py` (creates environment-specific copies from prod).

**Purpose:** Terraform-ready working directories, one per environment and per
GitLab repository. These are the folders you run `terraform plan` / `terraform apply`
from. Files here are reorganised, prefixed, and (for non-prod) have environment
tokens substituted.

**Folder structure:**

```
terraform-export-flat/
├── prod/                          ← organised from gcp-exports/prod/
│   ├── {repo_name}/               ← one folder per GitLab repo
│   │   ├── ds_{dataset_id}.tf     ← BigQueryDataset resource
│   │   ├── t_{dataset_id}_{table_id}.tf    ← BigQueryTable resource
│   │   ├── r_{dataset_id}_{routine_id}.tf  ← BigQueryRoutine resource
│   │   └── imports.tf             ← auto-generated import blocks
│   └── _unmapped/                 ← datasets not claimed by any repo
│       └── t_{dataset_id}_{table_id}.tf
│
├── prod_test/                     ← copy of prod/ with prod→test substitution
│   └── {repo_name}/
│       └── (same flat layout)
│
└── prod_dev-gke/                  ← copy of prod/ with prod→dev-gke substitution
    └── {repo_name}/
        └── (same flat layout)
```

**Filename prefixes:**

| Prefix | Resource type |
|---|---|
| `ds_` | `google_bigquery_dataset` |
| `t_` | `google_bigquery_table` (regular table, view, materialized view, external) |
| `r_` | `google_bigquery_routine` (UDF, stored procedure) |

**Key differences between `prod/`, `prod_test/`, and `prod_dev-gke/`:**

| What changes | prod/ | prod_test/ | prod_dev-gke/ |
|---|---|---|---|
| `project = "..."` | `tefde-gcp-fastoss-prod` | `tefde-gcp-fastoss-test` | `tefde-gcp-fastoss-dev-gke` |
| KMS key name | `ndl-prod-kms-thales-key-ew3` | `ndl-test-kms-thales-key-ew3` | `ndl-dev-kms-thales-key-ew3` |
| Label values (e.g. `prod_live`) | `prod_live` | `test_live` | `dev_live` |
| SQL query bodies | unchanged | unchanged | unchanged |
| Table/routine names | unchanged | unchanged | unchanged |

> The substitution intentionally leaves SQL query content untouched.
> Only the GCP project ID is replaced inside SQL heredoc blocks.

**`imports.tf` — what it contains:**

Auto-generated by `organize_tf_export_flat.py`. One `import {}` block per
resource, converting the `# terraform import TYPE.NAME ID` comment from each
`.tf` file into a native Terraform import block:

```hcl
import {
  id = "projects/tefde-gcp-fastoss-prod/datasets/il_5gias/tables/some_table"
  to = google_bigquery_table.il_5gias_some_table
}
```

**How to regenerate:**

```bash
# Step 1 — reorganise prod export into flat structure
python ~/remediation/"TEF remediation/scripts/organize_tf_export_flat.py" \
  --exports-dir ~/gcp-exports \
  --mapping-file ~/dataset_repo_map.json \
  --env prod

# Step 2 — propagate prod/ into prod_test/ and prod_dev-gke/
python ~/remediation/"TEF remediation/scripts/propagate_tf_env.py" \
  --flat-dir ~/terraform-export-flat
```

**How to use for Terraform:**

```bash
# Example: apply for the integration_layer repo in test environment
cd ~/terraform-export-flat/prod_test/integration_layer
terraform init
terraform plan
terraform apply
```

## Workflow overview

```
BigQuery API (prod)
        │
        ▼
export_bq_to_tf.py
        │
        ▼
~/gcp-exports/prod/projects/.../BigQuery{Dataset|Table|Routine}/
        │
        ▼
organize_tf_export_flat.py  ←── dataset_repo_map.json
        │
        ▼
~/terraform-export-flat/prod/{repo_name}/
        │
        ▼
propagate_tf_env.py
        │
        ├──▶ ~/terraform-export-flat/prod_test/{repo_name}/
        │
        └──▶ ~/terraform-export-flat/prod_dev-gke/{repo_name}/
```
